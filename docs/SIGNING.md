# Подпись кода (SignPath Foundation)

Подпись бесплатная для открытых проектов: сертификат выдаёт SignPath Foundation, подписывает сервис SignPath.io. Сам ключ нам не доступен, подписание идёт только из CI после ручного одобрения. Текст политики для пользователей — раздел «Code signing policy» в [README](../README.md).

## Что делает репозиторий

| Файл | Зачем |
|---|---|
| `Directory.Build.props` | метаданные файлов: Product=`Chistovik`, Company=`Egoist`, Copyright, версия |
| `.signpath/exe-dll.xml` | конфигурация артефакта для стадии 1: `Chistovik.*.exe` и `Chistovik.*.dll` в `publish-x64` и `publish-arm64` |
| `.signpath/msi.xml` | конфигурация артефакта для стадии 2: `Chistovik-*.msi` |
| `.github/workflows/release.yml` | по тегу `vX.Y.Z`: тесты → publish → подпись exe/dll → MSI из подписанных файлов → подпись MSI → черновик релиза |
| `tools/build-release.ps1` | `-SkipMsi` (стадия 1) и `-PublishRoot <папка>` (стадия 2); локально без параметров собирает неподписанные пакеты |

Подписывать нужно и exe/dll, и MSI: агент запускается с повышением, и UAC показывает издателя именно у `Chistovik.Agent.exe`. Сторонние файлы (.NET, SQLite) не подписываются: у них подписи вендоров или это файлы третьих сторон.

## Что должен сделать владелец (я этого не делал)

1. **Репозиторий.** Создать публичный репозиторий на GitHub (в тексте README и заметок предположено `egoist-ai1/chistovik`; если имя другое, поправить ссылки), запушить код. Нужен хотя бы один выпуск в подписываемой форме: сначала можно выложить неподписанный 0.2.0 как предварительный.
2. **Заявка.** Подать заявку на [signpath.org/apply](https://signpath.org/apply). В заявке: лицензия GPL-3 (OSI), публичный репозиторий, цель программы (удаление программ и управление настройками Windows), ссылка на раздел «Code signing policy» и на отсутствие сетевого кода. Решение за SignPath Foundation: у утилит, меняющих системные настройки, вопросы вероятны. Ответ на них: всё делается по явному действию пользователя, до применения показывается превью, есть журнал и откат, права запрашиваются через UAC.
3. **Аккаунт SignPath.** Включить многофакторную аутентификацию (она обязательна для всех с правом подписи). После одобрения в организации создать проект со slug `chistovik`.
4. **Источник сборки.** В проекте SignPath подключить GitHub.com как доверенную систему сборки и привязать репозиторий.
5. **Конфигурации артефактов.** Создать две конфигурации и вставить в них содержимое `.signpath/exe-dll.xml` (slug `exe-dll`) и `.signpath/msi.xml` (slug `msi`). SignPath проверит синтаксис при сохранении; если для атрибута `product-name` или набора файлов он потребует иную запись, поправить XML там и в репозитории.
6. **Политика.** Политика подписи `release-signing` (сертификат Foundation): требовать ручное одобрение; в Approvers должен быть владелец. Роли (Authors, Reviewers, Approvers) пока один человек: владелец репозитория.
7. **Секреты GitHub.** В репозитории: секрет `SIGNPATH_API_TOKEN` (токен CI-пользователя SignPath), переменные `SIGNPATH_ORGANIZATION_ID` и `SIGNPATH_PROJECT_SLUG` (`chistovik`). Токен никому не показывать и не писать в файлы.
8. **Выпуск.** Тег `v0.2.0` на коммите, где версия в `Directory.Build.props` равна `0.2.0`. Workflow дважды запросит одобрение в SignPath (exe/dll, затем MSI), создаст черновик релиза; проверить подписи на скачанных файлах и опубликовать черновик.

## Что не проверено

- Workflow и конфигурации артефактов не запускались: нет репозитория на GitHub и проекта SignPath. Синтаксис XML сверен с документацией SignPath; входы действия `signpath/github-action-submit-signing-request@v3` — с его `action.yml`.
- То, что действие распаковывает подписанный архив в `output-artifact-directory` с сохранением структуры папок, проверится на первом запуске.
- Локально проверена сборка MSI из готовых publish-папок (`-PublishRoot`) и обычная сборка без параметров; подпись при этом не использовалась.

## Если подписи не будет

Выпуск работает и без неё: `tools/build-release.ps1` даёт неподписанные MSI, SmartScreen покажет «неизвестный издатель». Тогда заметки о выпуске нужно править: убрать раздел про подпись и последнюю фразу про цифровую подпись.
