# Чистовик: план реализации готового приложения

Дата: 22.10.2026. Основа: прототип 0.3, итог совета (`02-итог-совета-и-план.md`), досье фактов. Решения по стеку и безопасности дал архитектор (Fable); я свёл их в план, добавил порядок работы, структуру репозитория и рекомендации по открытым вопросам. Оценки в днях — мои допущения для одного человека с ИИ-помощниками, не замер.

## 0. Коротко

- **Стек:** C# / .NET 10 (LTS), WPF. Движок на .NET, не на Go: MSI API, Appx PackageManager, Task Scheduler COM, SCM, Restart Manager, ETW в .NET родные; два рантайма и обмен между ними ничего не дают.
- **Три процесса:** интерфейс без прав, общее ядро, повышенный агент по UAC. Агент принимает только заранее описанные операции по named pipe, произвольных команд нет.
- **Главная гарантия безопасности:** в агенте нет операции «удалить файл». Есть только «перенести в карантин» и «очистить карантин». Закрытые зоны проверяются заново на стороне агента, по хэндлу, а не по строке пути.
- **Журнал:** SQLite, запись шага до выполнения, восстановление после сбоя. Любое действие (твик, режим, удаление) откатывается из той же записи.
- **Порядок:** сначала центр управления на обратимых правках (релиз 0.1), потом движок удаления (релиз 0.2). Так журнал, откат и агент обкатываются на безопасном, прежде чем понесут удаление.
- **Срок:** 100–125 рабочих дней, примерно 5–6 месяцев при полной занятости. Это главный риск: у владельца много параллельных проектов, поэтому релизы нарезаны так, чтобы каждый был самодостаточным.
- **Подпись:** для себя не нужна. До появления подписи упор на воспроизводимую сборку в CI, хеши в релизе и проверки на ложные срабатывания антивирусов.

## 1. Стек и процессы

| Часть | Решение | Почему |
|---|---|---|
| Язык и UI | C# / .NET 10, WPF, per-monitor DPI | skill `dotnet-desktop`; логика без `System.Windows`, тесты рядом; владелец знает платформу |
| Win32 | CsWin32 (генерация биндингов) | меньше ручного P/Invoke |
| Appx | CsWinRT, `PackageManager` | инвентарь и удаление MSIX |
| Планировщик, брандмауэр | COM-интероп (Task Scheduler 2.0, `HNetCfg.FwPolicy2`) | |
| Хранилище | SQLite в режиме WAL (`Microsoft.Data.Sqlite`) | выборки по вендорам, откат по одному артефакту, читатель параллельно писателю |
| Сборка | `win-x64` и `win-arm64`, self-contained папкой (не single-file) | антивирусные эвристики и распаковка при старте; эмуляция x64 на ARM64 теряет перенаправление реестра |

**Отвергнуто.** Go-движок как в прототипе: тяжело с MSI, WinRT, Task Scheduler, ETW. Tauri: тот же слой Win32 на Rust, которого владелец не знает, плюс зависимость от WebView2. WinUI 3: упаковка и окна сложнее без выигрыша для тёмной темы. Постоянная служба: резидент и метки антивирусов, совет был против.

### Процессы

```
Chistovik.App (WPF, без прав)  ──named pipe──▶  Chistovik.Agent (admin, по UAC)
        │                                              │
        └──────▶  Chistovik.Core  ◀────────────────────┘     Chistovik.Native (CsWin32, COM, WinRT)
   Policy · Inventory · Leftovers · Plan/Draft · Journal · Quarantine · Undo
```

- **`Chistovik.exe`** читает инвентарь (HKLM читается без прав), рисует черновики, читает журнал. Ничего опасного сам не делает.
- **`Chistovik.Agent.exe`** с манифестом `requireAdministrator`. Запускается из интерфейса через `ShellExecute runas`. Отказ от UAC даёт режим просмотра. Один экземпляр (mutex). Через 5 минут простоя завершается.
- **Канал:** `\\.\pipe\Chistovik.<SessionId>.<GUID>`, GUID приходит агенту аргументом. Доступ только у SID запустившего пользователя и SYSTEM. При каждом подключении агент проверяет: PID клиента (`GetNamedPipeClientProcessId`), путь образа (`QueryFullProcessImageName`) совпадает с `Chistovik.exe` рядом с агентом, SHA-256 файла совпадает с зашитым при сборке, сессия та же. Когда появится подпись Authenticode, добавится сверка подписи.
- **Протокол:** JSON с префиксом длины. Запросы — закрытое множество типов: `ApplyRegistryValue`, `SetServiceStart`, `SetTaskEnabled`, `ApplyPowerSetting`, `MoveToQuarantine`, `PurgeQuarantine(opId)`, `UndoStep(stepId)`, `RunUninstaller(packageId)` и т. п. Пути к программам и команды в запросе не передаются: для `RunUninstaller` агент сам берёт строку удаления из своего инвентаря. Данные интерфейса считаются недоверенными, политика исполняется в агенте заново.
- **Вариант Б (если «только для себя, упрощай»):** один повышенный процесс. Экономит около 1,5 недели, но закрытые зоны перестают переживать баг интерфейса, а drag-and-drop из Проводника ломается из-за UIPI. Архитектура модулей при этом не меняется, `Core.Policy` остаётся единственной точкой входа.

### Хранение

- `%ProgramData%\Chistovik\`: `chistovik.db` (пишет только агент; запись у Admins и SYSTEM, чтение у Users).
- `%LocalAppData%\Chistovik\settings.json`: настройки пользователя.
- Карантин: `<том>:\Chistovik.Quarantine\<opId>\<n>\`, скрытый и системный, доступ Admins. Свой корень на каждом томе, чтобы перенос был переименованием без копирования.
- Таблицы: `Operation`, `Step` (вид, до, после, состояние), `Package`, `Artifact`, `Evidence`, `QuarantineItem`. Срок хранения записей 90 дней.

## 2. Безопасность: как закрытые зоны переживают баг

`Core.Policy` — единственный модуль, который может сказать «можно». Вход: канонический путь, ключ, имя службы или задачи. Выход: `Allow`, `Deny(причина)` или `ExpertOnly(причина)`. Правила зашиты в сборку ресурсом и не настраиваются.

**Защищённые службы.** Прежние: WinDefend, mpssvc, RpcSs, Dhcp, Dnscache, EventLog. Предлагается добавить: WdNisSvc, Sense, SecurityHealthService, wscsvc, TrustedInstaller, Schedule, LSM, Winmgmt (список утвердить).

### 2.1. Как программа распознаёт любую службу, задачу и файл на любом устройстве

Решение владельца: защита не ограничивается списком имён, программа должна уверенно понимать, что перед ней, на любом ПК. Безошибочность в 100 % недостижима (на чужом компьютере может быть что угодно), поэтому правило такое: **что не распознано точно, то только показываем, но не меняем.** Ошибка в сторону «не тронули» безопасна, ошибка в сторону «тронули» нет.

Распознавание идёт по признакам, а не по именам. Каждый признак даёт баллы, итог — один из классов.

| Признак | Как читается | Что означает |
|---|---|---|
| Подпись файла | Authenticode, издатель Microsoft или производитель оборудования | Системная или драйверная: только чтение |
| Расположение | `ImagePath` службы или действие задачи в `System32`, `SysWOW64`, `WinSxS`, `DriverStore`, `Windows` | Системная: только чтение |
| Тип | драйвер ядра или файловой системы (`SERVICE_KERNEL_DRIVER`), общий процесс `svchost` | Системная: только чтение |
| Защита процесса | PPL, антивирусная и защитная служба (Defender, Security Center, драйверы сторонних антивирусов) | Защищённая: запрет |
| Зависимости | от службы зависят другие (`EnumDependentServices`), она в цепочке загрузки | Критичная: запрет |
| Каталог известных | встроенный список имён и описаний Microsoft и популярных производителей (учебный, не защитный: он только подсказывает, что это, и как безопасно взаимодействовать) | Подсказка в интерфейсе |
| Принадлежность программе | `ImagePath` или задача указывают внутрь `InstallLocation` установленной программы | Можно менять вместе с этой программой |
| Всё остальное | не подошло ни под один признак | Неизвестная: только чтение и пометка «не уверен» |

Что делает каждый класс: **запрет** (кнопки нет, агент отклоняет запрос), **только чтение** (показываем, объясняем, не меняем), **можно менять** (есть откат, нужен «Применить»). Классификатор работает в агенте, а не в интерфейсе, поэтому ошибка интерфейса не откроет защищённое. Стартовый список защищённых служб остаётся как нижняя граница: WinDefend, mpssvc, RpcSs, Dhcp, Dnscache, EventLog, WdNisSvc, Sense, SecurityHealthService, wscsvc, TrustedInstaller, Schedule, LSM, Winmgmt.

Для проверки классификатор прогоняется на каждой виртуальной машине (Win10, Win11 Home, Win11 Pro) по всем службам и задачам, результат сверяется с ручной разметкой выборки. Критерий приёмки: ни одна системная или защищённая служба не получает класс «можно менять». Нужен ещё отчёт о неопознанных, чтобы расширять каталог.

**Запретные ключи.** Политики Defender и UAC (`EnableLUA`), SmartScreen, `FeatureSettingsOverride`, `CI\Policy`, `nointegritychecks`, `Services\<защищённые>`, `WindowsUpdate`, сетевые `Tcpip\Parameters`, `Dnscache`, `Interfaces`, прокси WinHTTP и WinINET.

**Четыре слоя защиты файлов:**

1. В агенте нет удаления файла вне карантина. Есть `MoveToQuarantine` (переименование на том же томе) и `PurgeQuarantine(opId)`, которая удаляет только внутри корня карантина, проверенного по конечному пути.
2. Канонизация перед проверкой: открыть с `FILE_FLAG_BACKUP_SEMANTICS | FILE_FLAG_OPEN_REPARSE_POINT`, взять `GetFinalPathNameByHandle(VOLUME_NAME_GUID)`, сверить с зонами, приведёнными к GUID томов через `SHGetKnownFolderPath`. Точка повторного разбора внутри дерева переносится как ссылка, а не как цель.
3. Атрибуты: владелец TrustedInstaller или SYSTEM — запрет; файл под защитой SFC (`SfcIsFileProtected`) — запрет.
4. Действие по хэндлу: `SetFileInformationByHandle(FileRenameInfoEx)` на уже проверенном хэндле закрывает окно между проверкой и действием (TOCTOU).

**Реестр.** Сначала `RegCopyTree` в `HKLM\SOFTWARE\Chistovik\Quarantine\<opId>\<n>` и текстовый `.reg`, потом `RegDeleteTree` исходного. Удалять можно только ключи, у которых есть запись `Evidence` уровня не выше L2 (или L3 с флагом эксперта). Агент отказывает «голым» путям.

**Повышение защиты.** Любое ослабление идёт только через явный UAC. Экспертный режим не открывает системные зоны (WinSxS, DriverStore, WindowsApps, Installer, Windows, NonRemovable), это проверяется тестом.

## 3. Журнал и откат

**Запись шага:** `Step {id, opId, order, kind, target, before, after, state, error}`, где `state` — `pending | done | undone | failed | skipped`.

Что хранится в `before` и `after`:

| Объект | Содержимое |
|---|---|
| Значение реестра | тип и данные или «отсутствует» |
| Ключ реестра | ссылка на копию в карантине |
| Служба | тип запуска, отложенный автозапуск, работала ли, снимок конфигурации |
| Задача | включена ли, XML (`IRegisteredTask.Xml`) |
| Питание | GUID схемы, подгруппа, параметр, значения от сети и от батареи, активная схема |
| StartupApproved | исходные 12 байт |
| Файл | исходный путь, путь в карантине, SHA-256, атрибуты, времена, владелец, SDDL, цель ссылки |

**Порядок выполнения.** Записать `Step(pending)` в SQLite, выполнить, пометить `done`. Перед выполнением сравнить текущее состояние с `before`: если оно уже равно `after`, шаг сразу `done` (повтор после краша); если не равно ни `before`, ни `after`, шаг `failed("изменено извне")` и операция останавливается с честным итогом («вернули 41 из 43»).

**Восстановление.** При старте агент ищет `pending` и достраивает состояние по факту (исходник исчез и копия в карантине есть — значит `done`).

**Откат.** Те же шаги в обратном порядке с проверкой `after`. Расхождение — вопрос «перезаписать текущее?». Режим — это операция с дочерними шагами, откат режима откатывает детей.

Журнал и файловая система не атомарны, поэтому используется запись до выполнения плюс восстановление, а не попытка собрать транзакцию.

## 4. Движок удаления

### Инвентарь

- Реестр Uninstall: x64, x86, HKCU (как в `inventory.ps1`), добавить `WindowsInstaller`, `SystemComponent`, `NoRemove`, `ParentKeyName`.
- MSI: `MsiEnumProductsEx` по всем контекстам, `MsiGetProductInfoEx`; для L0 — `MsiEnumComponents` и `MsiGetComponentPath`; для L4 — `MsiEnumClientsEx` (больше одного клиента значит общий компонент).
- MSIX: `PackageManager.FindPackages()` для всех пользователей. Каркасы, ресурсные и системные пакеты показываются как защищённые.
- winget: база `installed.db` в `%LocalAppData%\Packages\Microsoft.DesktopAppInstaller_8wekyb3d8bbwe\LocalState\` либо разбор `winget export`. **Путь и схему проверить на ПК владельца.**
- Steam (`libraryfolders.vdf`, `appmanifest_*.acf`, удаление через `steam://uninstall/<appid>`) и Epic (`LauncherInstalled.dat`): в версии 1 только показать и открыть лаунчер.
- Другие профили (офлайн NTUSER.DAT): не в первых релизах.

### Запуск деинсталлятора

- Разбор строки: самый длинный существующий префикс.
- `msiexec /I|/X{GUID}`: `MsiSetInternalUI(BASIC)`, `MsiConfigureProductEx(ABSENT, "REBOOT=ReallySuppress")`. Код 3010 означает «нужна перезагрузка».
- MSIX: `RemovePackageAsync(RemoveForAllUsers)`.
- EXE: `QuietUninstallString`, если есть. Иначе интерактивно. Тихие ключи (NSIS `/S`, Inno `/VERYSILENT /NORESTART`) подставлять только при распознанной сигнатуре файла, не угадывать.
- Ожидание: процесс в Job Object без `BREAKAWAY_OK` и порт завершения `ACTIVE_PROCESS_ZERO`; дополнительно ждать освобождения мьютекса `Global\_MSIExecute` и исчезновения процессов с образом внутри `InstallLocation` (опрос раз в 2 с, по таймауту вопрос пользователю).
- Перед запуском Restart Manager (`RmRegisterResources`, `RmShutdown` без принуждения). `TerminateProcess` для чужих программ не используется.

### Поиск остатков

- **Снимок до и после.** Файлы: USN-журнал (`FSCTL_QUERY_USN_JOURNAL` запоминает `NextUsn`, затем `FSCTL_READ_USN_JOURNAL`). На ReFS, Dev Drive и FAT поддержку проверить; иначе обход каталогов-кандидатов и честная пометка «дифф неполный». Реестр: снимки кандидатных поддеревьев (`SOFTWARE\<Vendor>`, `Uninstall`, `Services`, `Run*`, `StartupApproved`, `Classes\CLSID|Applications|App Paths`, `TaskCache\Tree`, `SharedDLLs`), а не всего HKLM.
- **Уровни уверенности.**
  - L0: дерево `InstallLocation`, MSI-компоненты без других клиентов.
  - L2: служба с `ImagePath` в дереве, задача с действием в дереве, ярлык `.lnk` на цель в дереве, записи Run, правила брандмауэра (`ApplicationName`), `App Paths`, `Applications\<exe>`, CLSID `InprocServer32` в дереве.
  - L3: папки `%AppData%`, `%LocalAppData%`, `%ProgramData%` по имени вендора и продукта. Никогда не отмечаются заранее.
  - L4 (не трогаем): общий ключ вендора, `SharedDLLs` больше 1, рантаймы, чужой `InstallLocation`.
  - L1 — наблюдение (см. ниже).
- **Точка восстановления.** `SRSetRestorePoint` с `BEGIN_SYSTEM_CHANGE`, затем проверка через WMI `root\default:SystemRestore` по `SequenceNumber`. Лимит «одна точка за 24 часа» обходится временным `SystemRestorePointCreationFrequency=0` с возвратом значения в `finally` и при восстановлении. Если защита системы выключена, молча не включать, показать ссылку в Параметры. В чеке сказать прямо: точка не хранит личные файлы и может быть вытеснена.
- **Карантин.** Перенос на том с манифестом (SHA-256, SDDL, атрибуты, времена), хранение 7 дней. Очистка только при запуске агента: резидента нет, это написать в интерфейсе. Службы: экспорт ключа, остановка, `DeleteService`; откат — `CreateService` из снимка. Задачи: XML, `DeleteTask`; откат `RegisterTask`. Правила брандмауэра: сериализация свойств, `Rules.Remove`; откат `Rules.Add`.
- **«Под наблюдением».** Версия 1.5 строится на тех же снимках (USN и реестр вокруг запуска установщика), тот же код, что у диффа удаления. ETW (провайдеры Kernel-File, Kernel-Registry, Kernel-Process через TraceEvent) — версия 2: на ARM64 уверенности нет, а сессия ETW повышает риск меток антивирусов.

| Твики реестра | каталог JSON в ресурсах (id, ключ, вкл/выкл, права, перезапуск, откат); запись плюс `SystemParametersInfo` (`SPI_SETANIMATION`, `SPI_SETDRAGFULLWINDOWS`, `SPI_SETMENUSHOWDELAY`) и `WM_SETTINGCHANGE` | HKLM: админ | произвольной записи нет (решение владельца); спорные твики (например меню Win11) помечать |
| Обозреватель реестра | чтение любых ключей, `RegNotifyChangeKeyValue` для «изменилось» | нет | «кто пишет» только через ETW Kernel-Registry (админ, TraceEvent); страница по требованию, при неудаче честно «недоступно» |
| Окна | `EnumDisplayMonitors`, `GetMonitorInfo(rcWork)`, `EnumWindows` с фильтром (видимое, без владельца, не cloaked), `SetWindowPlacement` и `SetWindowPos` с поправкой на невидимую рамку (`DWMWA_EXTENDED_FRAME_BOUNDS`), DPI на монитор | повышенные окна: через агента | без резидента не будет автопривязки при перетаскивании, восстановления после отключения монитора, интеграции с Snap Win11. В версии 1 зоны по кнопке и горячей клавише |
| Мониторинг | PDH (`% Processor Utility`, `Disk Bytes/sec`, `Network Interface Bytes Total/sec`), `GlobalMemoryStatusEx`, процессы через `NtQuerySystemInformation` или дельты `GetProcessTimes` / `GetProcessIoCounters`, `SetPriorityClass` | чужие процессы: админ | критические, PPL и SYSTEM-процессы завершать нельзя; «освобождено» и «здоровье» — оценка |

## 6. Тестирование

- **Стенд.** Hyper-V на хосте: ВМ Win10 22H2, Win11 24H2 Home, 25H2 Pro. Базовый чекпоинт, сценарий через PowerShell Direct, сравнение с чекпоинтом, откат. Истина — независимый снимок (`Get-ChildItem -Force` по корням и `reg export` ульев), а не наш движок.
- **Пациенты (20–30).** 7-Zip (MSI и EXE), Notepad++ (NSIS), Git for Windows (Inno), VLC, OBS, Python 3.x с Python Launcher (один вендор, два продукта), VC++ Redist x64 и x86 (пара, канарейка L4), Node.js (MSI), PowerToys, Telegram (портативный с ARP), Discord (Squirrel), VS Code (пользовательский и системный), установка через winget, два MSIX из Store, «сломанный» (деинсталлятор удалён). Пары и рантаймы обязательны: **0 ложных удалений — критерий приёмки**. Типы установщиков проверить при сборке корпуса.
- **Юнит-тесты без состояния Windows.** Разбор строк удаления на корпусе из реального `inventory.json`. Матчер зон — property-based (skill `property-based-testing`) на 300+ путях: регистр, `/`, `\\?\`, `\\.\C:\`, GUID тома, имена 8.3, `..`, точки и пробелы в конце, `%SystemRoot%`, junction из `Program Files` в `Windows`. Байты StartupApproved. Круговая проверка формата Step и отката.
- **Негативные тесты (блокируют релиз).**
  - `MoveToQuarantine("C:\Windows\WinSxS\x")` даёт `PolicyViolation`, файл цел, в журнале запись `denied`.
  - То же для junction, указывающего в закрытую зону.
  - `SetServiceStart("WinDefend")` отклоняется.
  - Неизвестный тип запроса: соединение рвётся.
  - Подключение к каналу чужим exe: отказ.
- **Интеграционные (`[VmOnly]`).** Удаление каждого пациента, дифф с истиной, полнота по уровням, ложные удаления, откат байт-в-байт (хеш и SDDL), обрыв агента посреди переноса в карантин и восстановление.
- **ARM64.** Юнит-тесты на раннере `windows-11-arm` (проверить при настройке CI). Интеграция требует реального устройства (вопрос 1).

## 10. Подпись и распространение (РФ)

- Для себя подпись не нужна: UAC покажет «Неизвестный издатель», SmartScreen предложит «Всё равно запустить». Smart App Control на свежих Windows 11 заблокирует без обхода (оценка совета: 10–20 % машин).
- **До подписи.** Воспроизводимая сборка в GitHub Actions, SHA-256 в заметках релиза, без упаковщиков и обфускации, без single-file, без длинных строк PowerShell, сухой прогон по умолчанию, без автозапуска. Перед каждым релизом VirusTotal; при ложном срабатывании заявка в WDSI, «Лабораторию Касперского», ESET.
- **Пути подписи (из отчёта совета).** SignPath Foundation (бесплатно для открытого кода под GPL, вероятность одобрения около 35 %, растёт при публичной истории) — основной. ИП на НПД и GlobalSign через LeaderSSL около 24 900 ₽ в год (есть риск отзыва) — страховка. Store (MSIX подписывает Microsoft) — запасной путь, доступность физлицу из РФ не подтверждена. EV мгновенной репутации больше не даёт.
- **Обновления.** Сначала переносимый ZIP, проверка версии через GitHub Releases и ссылка (без автозамены). Затем Velopack (MIT, поддержка arm64 и реакция антивирусов на `Update.exe` проверить) либо собственная схема: скачать, сверить SHA-256, подменить при перезапуске. Если делать установщик, он обязан корректно регистрироваться в «Программах и компонентах» и удаляться дочиста (он первый «пациент» бенчмарка).

## 12. Решения по вопросам (ответы владельца 22.10.2026)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Устройство ARM64 | Нет. ARM64 собираем и гоняем юнит-тестами, в релизе пишем «не проверено на железе» |
| 2 | Постоянная фоновая программа в трее («резидент») для окон | Нет. Зоны окон по кнопке и горячей клавише, пока Чистовик открыт. Вернёмся после M5 |
| 3 | Однопользовательский ПК | Да. Профили других пользователей не трогаем |
| 4 | ReFS и Dev Drive | Нет. Проверено на ПК: диски C и R — NTFS. Дифф файлов через USN-журнал работает |
| 5 | Заявка на бесплатную подпись (SignPath) | Позже. Подпись не блокирует работу «для себя». Подавать после релиза 0.1, для неё код должен быть открытым |
| 6 | Защищённые службы | Не список, а правила распознавания: раздел 2.1 |
| 7 | Один процесс или два | Два (интерфейс без прав и маленький рабочий с правами). Пользователь видит один запрос UAC при запуске |

Исходные формулировки вопросов и рекомендации оставлены ниже для справки.

1. **Есть ли устройство ARM64** (Surface, Dev Kit, Mac с Parallels)? Рекомендация: если нет, ARM64 собираем и гоняем юнит-тестами, на релизе пишем «не проверено на железе».
2. **Разрешён ли резидент в трее** для окон (автопривязка, память топологии мониторов, очистка карантина)? Рекомендация: нет в версиях 0.1 и 0.2, вернуться к вопросу после M5.
3. **ПК однопользовательский?** Рекомендация: да, другие профили и офлайн NTUSER.DAT не делаем.
4. **Есть ли тома ReFS или Dev Drive?** Влияет на USN-дифф. Рекомендация: проверить командой на вашем ПК до M3.
5. **Подавать заявку в SignPath сейчас** (это фиксирует GPL и публичный репозиторий с первого коммита) или фаза «для себя» без подписи? Рекомендация: GPL-3.0+ и публичный репозиторий с M0, заявку подать после релиза 0.1.
6. **Расширить список защищённых служб** до предложенного (WdNisSvc, Sense, SecurityHealthService, wscsvc, TrustedInstaller, Schedule, LSM, Winmgmt)? Рекомендация: да.
7. **Один процесс или два** (вариант Б в разделе 1)? Рекомендация: два, разница 1,5 недели, а гарантия закрытых зон того стоит.

## 13. Что не проверено

Всё ниже брать с проверкой, не из памяти: путь и схема `installed.db` у winget; событие 101 `Diagnostics-Performance` как источник времени автозагрузки; поддержка USN на ReFS; TraceEvent на arm64; раннер `windows-11-arm` в Actions; ветки WOW и ARM32 в реестре на 24H2 и новее; сообщение выхода Проводника через `Shell_TrayWnd`; доступность схемы «Максимальная производительность» через `duplicatescheme` на Home; реакция антивирусов на Velopack. Сроки в днях — допущение.
